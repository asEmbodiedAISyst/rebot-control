# 设计决策

**独立实现，不是 Seeed `reBotArm_control_py` 的 fork。** 那个仓库没有许可证，它的代码不能用在开源包里。
从 Seeed 的资料里只取了事实：URDF（CERN-OHL-W，见 NOTICE）、CAN id 和默认增益。

**Python，单进程，一个伺服线程。** 150 Hz、每个 tick 约 20 us 的计算量，Python 完全应付得来。
C++ 或实时内核的方案更快，但对科研用途来说更难安装、更难改。如果真机上伺服超时成了问题，
下一步是把伺服循环放进单独的进程，用共享内存传递目标和状态。这不需要改 API。

**用 MIT 模式连续下发目标，不用驱动器的位置模式。** MIT 模式可以直接控制刚度和阻尼，可以加力矩前馈，
还能做只有重力补偿的模式。这些位置模式都做不到，而推动实验需要它们。

**重力前馈按实测的 q 计算，不按目标计算。** 电机要把机械臂保持在它实际所在的位置，需要的正是这个力矩。
加上力矩上限后，错误的目标也产生不了很大的前馈。

**在伺服循环里对目标插值。** 30 Hz 的台阶听得见，还会激起结构振动。插值会带来一个控制周期的延迟，
笛卡尔限制和按跟随误差减速的机制已经把它考虑在内。

**速率限制相对于上一个目标，而不是实测位置。** 相对实测位置做速率限制，限住的是 PD 力矩而不是速度：
落后的关节永远得不到更大的目标。

**带先验的静态重力标定。** 它快（5 到 10 分钟），安全（只有慢速运动和保持），而且正好给出前馈需要的参数。
完整的动态辨识以后再加。

**仿真器由 Pinocchio 模型生成。** 运动学和动力学只有一个来源，另外提供显式的“真值”覆盖。
标定工具的测试方法是：看它们能不能找回控制器并不知道的参数。

**工具就是数据。** 一个工具是一份 YAML，包含 TCP、负载、home 位姿和笛卡尔限制。换工具不用改代码，
这正是本库的目的。

**退出时分阶段折叠，出错后不折叠。** 正常退出总是让机械臂回到休息位姿。出了原因不明的错误以后，
让它运动反而是更危险的选择。

**只有有意为之才卸力**（2026-11-16 决定，在真机上跑过最初几次之后）。早先的做法是出错后卸力，
这会让展开的机械臂连同工具一起砸到桌面上。对一台装着 pusher、重 3 kg 的机械臂来说，原地保持是更安全的默认行为：
电机会无限期执行最后一帧（CAN 超时为 0），本库在放手之前先发一帧干净的保持帧，下一个程序再把保持接管过去。
代价是在两个程序之间，有一台无人监管、带着电的机械臂；结束这个状态的是操作者（`rebot-control release`）。
过温时默认仍然卸力：驱动器烧毁比机械臂掉下来更糟。

**`connect()` 对力矩状态不做任何假设。** 上一个程序可能让电机留在保持状态，所以新程序最先发出的帧不能是零增益帧。
探测帧是一帧全增益的保持帧，目标就是刚读到的角度。对正保持在那里的电机，它等于什么都没做；对未使能的电机也一样。

**许可证：MIT**（2026-11-09 决定）。它简短、宽松，适合一个希望别人能直接放进自己代码里的科研工具。
它与各项依赖兼容：Pinocchio（BSD-2）、MuJoCo（Apache-2.0）和 motorbridge。随包附带的 URDF 仍然采用
CERN-OHL-W-2.0（见 NOTICE）：修改过的版本必须保留该许可证并列出改动，`tools/make_arm_urdf.py` 会把这些写进文件头。
