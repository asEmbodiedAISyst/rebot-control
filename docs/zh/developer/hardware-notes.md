# 硬件说明

本页列出代码所依赖的 B601-RS 事实，以及每台机械臂上要回答的问题。真机测试的现场日志暂未公开。

## 代码依赖的事实

- 使用出厂零位时，电机原始角 = URDF 关节角（所有关节 direction 为 1、offset 为 0）。
- CAN id 为 1 到 6，反馈 id 为 0xFD，`rs-06` x 3 + `rs-00` x 3；SocketCAN，1 Mbit/s。
- 反馈只来自命令的应答。未使能的电机仍会应答 MIT 帧。
- 默认增益是 Seeed 插件默认值 x 0.8。以 150 Hz 连续下发，听得见的 30 Hz 台阶就消失了。
- 关节目标的整形：25 deg 跳变保护、90 deg/s 速率限制、0.1 s 滤波、10 deg 力矩上限。
- 堵转判据：跟随误差达到 10 deg 并持续 1 s，期间运动不到 1 deg。
- 展开时先动肩和肘。折叠时先动基座和腕，再动肩和肘。否则腕部会蹭到上臂。
- 重启或重新插拔后，`can0` 处于 DOWN 状态。
- B601-RS 上驱动器的 CAN 超时（参数 0x7028）为 0。本库每次连接时都会读取它。

## 程序意外终止后继续保持：背后的假设

程序异常退出后，本库让机械臂继续上着力矩；连接时如果机械臂已经使能，就把它接管过来；卸力要靠显式的释放
（[`../user/safety.md`](../user/safety.md)）。这套行为建立在下面几条关于电机和 motorbridge 的假设之上。
[真机测试计划](../user/hardware-test-plan.md)的第 2b 步会在机械臂上检查它们。

| # | 假设 | 如果不成立 |
| --- | --- | --- |
| 1 | 帧停发后，已使能的电机继续执行最后一帧 MIT 帧（CAN 超时为 0） | 程序一死，机械臂就掉下来 |
| 2 | `MotorState.status_code` 对未使能的电机为 0，对已使能的电机不为 0 | 连接时把已使能的机械臂当成未使能，发去零增益帧：机械臂掉下来 |
| 3 | 读参数（type 17）不会替换电机正在执行的 MIT 帧 | 程序连接时机械臂抖一下或下垂 |
| 4 | 释放 motorbridge 的句柄（`Motor.close`、`Controller.close`）不会向电机发送任何东西 | 程序断开时机械臂掉下来 |
| 5 | 未使能的电机会忽略增益不为零的 MIT 帧（连接时的探测帧） | 程序连接时，未使能的机械臂会变硬一帧 |
| 6 | 逐个电机的 `disable` / `ensure_mode` / `enable` 与 `disable_all` / `enable_all` 效果相同 | 使能失败 |

## 每台机械臂上要回答的问题

| # | 问题 | 方法 |
| --- | --- | --- |
| 1 | 每个关节的方向与 URDF 一致吗？ | 测试计划第 1 步 |
| 2 | 控制电脑上以 150 Hz 运行时有伺服超时吗？ | `rebot-control hold`，60 s |
| 3 | 每个 tick 的总线耗时是多少（6 次写入 + 轮询）？ | 在 `send_mit` / `read` 前后记录 `time.perf_counter()` |
| 4 | 用 URDF 模型时，重力补偿模式下每个关节漂移多少？ | 测试计划第 3 步 |
| 5 | 静止时力矩读数的偏置和噪声有多大？ | `calib gravity` 的输出（偏置、RMS） |
| 6 | 上报的力矩是在帧周期内的哪个时刻采样的？（它会使摩擦的 `fv` 产生偏差。） | 在 kp 和 2 kp 下各做一次 `calib friction`，比较 `fv` |
| 7 | 帧停发后会怎样？ | 测试计划第 2b 步 |
| 8 | 默认增益下的阶跃响应是什么样？ | `calib gains --check` |
| 9 | 腕部模型算出的 zeta 为 2 到 3，是真的吗？ | 比较 `zeta est` 和 `zeta model` |
| 10 | 基座坐标系的原点在桌面上吗（桌面处 z = 0）？ | home 位姿下的 TCP z，用尺子对照 |
| 11 | 驱动器接受的 MIT kp / kd 范围是多少？ | 带上限运行 `calib gains`，观察是否被限幅 |
